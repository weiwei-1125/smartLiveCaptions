# smartLiveCaptions — 设计文档（Design Spec）

- **日期**：2026-06-01
- **状态**：已通过头脑风暴，待评审
- **一句话**：一个 Windows 常驻底部字幕条，实时收麦克风、显示「原文 + 对照译文」，分**练口语**与**面试**两个模式，全程只用 OpenAI 一个 API key。

---

## 1. 目标与非目标

### 目标（Goals）
1. 实时把麦克风里的语音转成文字，**原文在上、对照译文在下**，逐字流式显示。
2. 两个使用模式：
   - 🗣️ **练口语（中 → 英）**：用户说中文，看英文翻译，可朗读、可看其他说法。
   - 🎧 **面试（英 → 中）**：麦克风收到的英文（不分角色）→ 看英文原文 + 中文翻译。
3. 像 Windows Live Captions 一样**常驻、置顶、半透明、不挡操作**。
4. 体感"秒出字"（转写 200–400ms 级延迟）。
5. 个人轻度使用成本控制在**约几美元/月**。

### 非目标（Non-goals，本期明确不做）
- ❌ 捕获系统声音 / 扬声器 loopback（仅麦克风）。
- ❌ 历史记录 / 复习 / 存盘（看完即走，仅内存中短暂滚动）。
- ❌ 多角色 / 说话人分离（diarization）。
- ❌ 中英混说一句话里逐词混排的极致质量（OpenAI 转写够用即可；不引入 Soniox）。
- ❌ 端到端语音翻译模型（`gpt-realtime-translate`）、语音对语音、影子跟读。
- ❌ 多变体（2-3 种地道说法）作为主线 —— 仅作练口语模式下的**按需**功能。

### 未来可扩展（Out of scope now, designed to allow later）
- 系统声音捕获（面试时直接收对方原始音频，绕过外放损耗）。
- 自动语言判断（替代手动模式开关）。
- ElevenLabs / Cartesia 等高质量语音（TTS 已设计为可切换）。
- 历史与复习、影子跟读（中文→英文语音朗读 + 录音对比）。

## 2. 用户与场景

**用户**：母语中文、正在提升英文口语 / 准备英文面试的个人开发者（本人）。

**场景 A · 练口语**：开着应用，随口说中文，立刻看到这句话的英文，点 ▶️ 听发音，必要时点 💡 看 2-3 种更地道的说法。

**场景 B · 手机面试**：手机开外放、电脑麦克风收音，面试双方说英文。用户看英文原文 + 中文翻译，实时跟上听不清/没听懂的部分。麦克风收到的所有英文都翻成中文，不区分是谁说的。

---

## 3. 核心行为（Functional Requirements）

### 3.1 统一显示规则
- 每个"话语块（utterance block）"= **原文行（上） + 译文行（下）**。
- 说话时原文**逐字流式**出现（带光标），识别"定稿"后触发翻译。
- 译文在原文下方，流式出现。

### 3.2 模式（手动开关）
| | 练口语 🗣️ | 面试 🎧 |
|---|---|---|
| 语言提示（送给转写）| `zh` | `en` |
| 方向 | 中文原文 → 英文译文 | 英文原文 → 中文译文 |
| ▶️ 朗读 | 显示（读英文译文）| 隐藏 |
| 💡 其他说法 | 显示（按需出 2-3 种地道英文）| 隐藏 |
| 默认 | ✅ | |

> 模式开关同时起两个作用：① 给转写**语言提示以提升准确率**（研究表明显式语言提示显著降低误判）；② 决定翻译方向。这比"让模型自动猜中/英"更可靠，尤其中英混说时。

### 3.3 朗读（▶️，仅练口语）
- 点击英文译文旁的 ▶️ → 调 TTS 朗读这一句 → 播放。
- 按需触发，仅点击时产生费用。

### 3.4 其他说法（💡，仅练口语，按需）
- 点击 💡 → 用文本 LLM 对这句中文生成 **2-3 种地道口语英文**（不分类，直接给说法）→ 在该块下方展开。
- 这是用户最初的核心想法，降级为按需功能，不拖慢主线翻译。

### 3.5 连续说话行为
- **滚动保留最近几句**（约 3–5 句）：新句在最下/当前位置，旧句向上滚动、逐渐变淡，更旧的折叠为单行原文后消失。
- 不存盘，纯内存、超出即丢弃。

### 3.6 成本控制
- **本地 VAD（voice activity detection）**：仅在检测到语音时才上传音频到转写服务，静音不传。

## 4. 架构

### 4.1 数据流
```
麦克风 ─► AudioCapture ─► VAD 门控
                              │（有语音才上传）
                              ▼
                    TranscriptionService  (gpt-realtime-whisper, 语言提示=模式)
                              │ 流式 partial / final
                              ▼
                    原文行（上）— 流式显示
                              │（句子 final 时）
                              ▼
                    TranslationService  (默认 gpt-5-nano / gpt-4.1-nano，可切换)
                              │ 流式译文
                              ▼
                    译文行（下）— 流式显示
                       ├─ ▶️ 点击 ─► TTSService (gpt-4o-mini-tts，可切换) ─► 播放
                       └─ 💡 点击 ─► VariantsService (文本 LLM) ─► 2-3 种说法
```

### 4.2 组件与职责（每个职责单一、接口清晰、可独立测试）

| 组件 | 职责 | 关键接口 | 依赖 |
|---|---|---|---|
| **AudioCapture** | 采集麦克风 PCM 帧 | `start()/stop()`, 输出 PCM 帧流 | 浏览器 getUserMedia / 系统音频 |
| **Vad** | 判断语音/静音，门控上传 | `feed(frame) → isSpeech` | — |
| **TranscriptionService** | 管理 OpenAI Realtime 转写 WebSocket，按语言提示转写 | `connect(langHint)`, 事件 `onPartial(text)`, `onFinal(text)`；`disconnect()` | OpenAI Realtime API |
| **TranslationService** | 文本翻译接口（可切换实现）| `translate(text, srcLang, tgtLang) → stream<token>` | OpenAI 文本模型（可换 DeepSeek 等）|
| **TtsService** | 文本转语音接口（可切换实现）| `speak(text) → audio` | gpt-4o-mini-tts（可换 ElevenLabs）|
| **VariantsService** | 中文 → 2-3 种地道英文 | `variants(zhText) → stream<variant>` | OpenAI 文本模型 |
| **CaptionStore** | 当前话语块 + 滚动历史（内存、有上限）+ 当前模式状态 | `pushPartial`, `commit`, `roll`, `setMode` | — |
| **OverlayUI** | 渲染底部字幕条：块、滚动、淡出、按钮 | 订阅 CaptionStore | — |
| **ModeController** | 练口语/面试切换；设置语言提示、方向、按钮可见性 | `setMode(practice\|interview)` | TranscriptionService, UI |
| **TrayController / Hotkeys** | 托盘菜单、热键：显示/隐藏、开关收音、切模式 | 系统托盘 + 全局热键 | Tauri |
| **Config** | 本地存储：API key、各模型选择、语音、模式、窗口位置/透明度/字号 | `get/set`, 持久化 | Tauri store |

> **可切换接口是关键设计**：`TranslationService`、`TtsService`、`TranscriptionService` 都是接口 + 具体实现，便于以后换模型/厂商（如翻译换 DeepSeek、TTS 换 ElevenLabs、转写换省钱档）而不动核心。

### 4.3 模型与档位（全 OpenAI，一个 key）
| 模块 | 默认实现 | 计费 | 备注 |
|---|---|---|---|
| 转写 | `gpt-realtime-whisper`（跟手档）| ~$0.017/min（~$1/hr）| 200–400ms partial；VAD 门控后实际更低 |
| 翻译 | `gpt-5-nano` 或 `gpt-4.1-nano`（可切 `gpt-4.1-mini`/`gpt-5.4-mini`）| 每句几乎为 0 | 流式；prompt 强调"地道、口语" |
| 朗读 | `gpt-4o-mini-tts` | ~$0.015/min，仅点击时 | 可切 ElevenLabs |
| 其他说法 | 同翻译的文本模型 | 按需、极低 | 不分类，直接给 2-3 种 |

### 4.4 技术栈与桌面实现
- **框架**：Tauri v2（安装包 ~3-10MB，内存 ~30-50MB），Web 前端（HTML/CSS）做悬浮窗 UI。
- **悬浮窗**：`transparent:true, alwaysOnTop:true, decorations:false`；**布局 A · 底部字幕条**；半透明深色背景。
- **点击穿透**：透明空白区穿透、字幕块/按钮可点 —— Tauri 用 Rust 侧光标轮询切换 `setIgnoreCursorEvents`（已知做法）。
- **麦克风**：前端 `getUserMedia` 取 PCM；处理 WebView2 麦克风权限。
- **密钥与调用**：OpenAI API key 存本地配置，API 调用走 **Rust 后端**（不在前端暴露 key）。
- **托盘 + 热键**：系统托盘常驻；全局热键显示/隐藏、开关收音、切模式。

## 5. UI / UX

- **底部字幕条**：贴屏幕底部、左右留边、半透明圆角深色面板。
- **话语块**：原文（练口语=蓝色中文 / 面试=绿色英文，带"你说的/收到的"小标签）在上；译文在下，左侧细色条。
- **按钮**（练口语译文行）：`▶️ 朗读`、`💡 其他说法`。
- **滚动**：当前块在底，历史向上滚动 + 渐淡，最旧折叠/消失。
- **顶部/托盘**：模式开关（🗣️练口语 / 🎧面试）、收音开关、设置入口。
- **可调**：窗口位置、透明度、字号（设置项）。

## 6. 错误处理与边界情况

| 情况 | 处理 |
|---|---|
| 麦克风权限被拒 | 引导用户授权；UI 提示，不崩溃 |
| 转写 WebSocket 断开 | 自动重连；重连期间提示"连接中" |
| 翻译/TTS API 报错或超时 | 在受影响的那一行就地显示错误 + 重试按钮；不影响其它块与字幕条 |
| 限流（rate limit）| 指数退避重试 |
| 转写为空/乱码/极短 | 跳过翻译，不生成无意义译文 |
| 语言判断与模式不符（例：练口语模式却说了英文）| 原文始终可见，用户可见可纠；提供一键切模式 |
| 网络中断 | 明确提示离线；恢复后自动续上（无离线兜底，本期不做本地模型）|
| 手机外放音质差（面试）| 语言提示=en 提升准确率；文档提醒此场景准确率会下降 |

## 7. 配置（本地持久化）
- OpenAI API key。
- 各模块模型/档位选择（转写档、翻译模型、TTS 语音/厂商）。
- 当前模式、窗口位置/透明度/字号、热键。

---

## 8. 成本模型（个人轻度使用估算）
- 转写：VAD 门控后，按实际说话时间计费；一天真说话十几二十分钟 → 月 ~$1-5。
- 翻译：每句几毫厘 → 可忽略。
- 朗读：仅点击时，$0.015/min → 月几毛到几块。
- **合计：约几美元/月。**

---

## 9. 风险与待验证
1. **OpenAI 转写对中英混说的准确率**：弱于 Soniox；靠模式语言提示缓解，需实测验证可接受。
2. **面试场景外放音质**：mic 收外放有损耗，准确率待实测。
3. **跟手延迟**：翻译每句 final 后 ~0.5-1s 跟上，连续快速对话时是否够用，待实测。
4. **Tauri 点击穿透 / WebView2 麦克风权限**：已知有小坑，预留调试时间。

---

## 10. 建议构建顺序（详细计划见后续 implementation plan）
1. **P1 核心管线**：麦克风 → VAD → 转写 → 原文显示 → 翻译 → 译文显示（先练口语模式，底部字幕条，置顶透明）。
2. **P2 模式与朗读**：加面试模式 + 模式开关（语言提示/方向/按钮）；加 ▶️ 朗读（gpt-4o-mini-tts）。
3. **P3 其他说法 + 滚动 + 打磨**：💡 按需变体；连续说话滚动/淡出；托盘、热键、设置、点击穿透打磨。

## 附：被否决的方案与理由（决策记录）
- **本地 Whisper（faster-whisper）**：慢（0.5-2s + 改字抖动），与"想要 Live Captions 那种秒出"冲突 → 否。
- **Soniox（云端，中英混说最强）**：曾入选；因转向全 OpenAI（一个 key、用户已有）+ 两个场景非重度混说 → 砍。
- **Azure / 传统 NMT 翻译层**：2026 LLM 翻译质量已反超 NMT，且本设计直接 LLM 翻译 → 不需要。
- **端到端 `gpt-realtime-translate`**：对"原文先显示 + 双向 + 省钱"不如"转写+文本翻译"流水线（双向几乎免费、原文更干净、更便宜）→ 否，留作未来语音同传扩展。
- **ElevenLabs TTS**：发音最像母语，但 +1 厂商 + 更贵；TTS 已设计为可切换，以后想升级零重构 → 本期用 gpt-4o-mini-tts。
